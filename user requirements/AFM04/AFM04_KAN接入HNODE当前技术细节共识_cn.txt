AFM04 中 KAN 接入 HNODE 的当前技术细节共识

一、总体定位

1. AFM04 中将直接使用 pykan，而不是自行重写 KAN。
2. KAN 在 AFM04/HNODE 中仅被视为一个功能化模块，而不是一个完整独立训练框架。
3. 因此，在 AFM04 中不会使用 pykan 自带的 fit() 训练框架；KAN 只负责前向输出，外层仍由 HNODE 的 RHS、rollout、loss、checkpoint 等机制管理。

二、模块边界

1. KAN 在 HNODE 中的输入保持与当前 MLP 一致，即当前时刻状态：

   (x1, x2, x3)

2. 第一版不引入额外输入变量，不额外加入 s、t 等输入。
3. KAN 的输出为单标量。
4. 该单标量对应接触力模块输出，并参与 RHS 积分。

三、网络结构

1. 当前先固定为一层 hidden layer。
2. width 固定为：

   [3, 5, 1]

3. 即：
   输入节点数 = 3
   hidden 层节点数 = 5
   输出节点数 = 1

四、pykan 相关设置

1. grid 先固定为：

   5

2. spline 阶数先固定为：

   k = 3

3. 当前不启用 adaptive grid update，grid 先保持 fixed。
4. symbolic_enabled 设为：

   False

5. auto_save 设为：

   False

6. noise_scale 设为：

   0.0

五、输入与输出尺度

1. 输入允许做归一化，以便更适配 pykan 的 grid / spline 数值范围。
2. 输出侧不采用硬编码固定常数 F_scale。
3. 输出幅值控制改为使用 g_nn / nn_gain 的思想进行标定。
4. 当前共识是：
   保留 g_nn 作为幅值标定标量；
   不恢复 w_pred。

六、与 AFM03/AFM04 当前设定的关系

1. AFM04 中不使用 w_pred。
2. KAN 替换当前 MLP 时，w_pred 不会一并恢复。
3. g_nn / nn_gain 仅保留其“输出幅值标定”作用，不再承担 gate 作用。
4. st1pl 当前仍然处于 trial_opt 关闭的语境下，因此 KAN 在 st1pl 中首先承担的是“前向评估模块”的角色。

七、当前不做的事情

1. 当前不使用 pykan 的 fit()。
2. 当前不启用 symbolic branch。
3. 当前不启用 auto_save。
4. 当前不启用 adaptive grid update。
5. 当前不在 st1pl 中开启 gradient-based trial optimization。
