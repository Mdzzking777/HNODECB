AFM04：如何把 AFM03 Julia 代码库功能克隆到 AFM04 Python 中去

当前修订要求（优先级最高）

目前 AFM04 的推进原则需要进一步收紧：

1. 当前要求不是“先做一个受 AFM03 启发的 Python 近似版本”，而是做真正的功能克隆；
2. 当前优先克隆的对象不是只有 `st1pl`，而是 AFM03 中 `stage1` 与 `st1pl` 的功能；
3. 其中唯一明确允许暂缓的是：
   `archi screening`；
4. 除 `archi screening` 外，`stage1/st1pl` 中现有的重要功能都应按 AFM03 去复现；
5. 当前 NN 也不应提前替换成 KAN，而应与 AFM03 保持一致，仍然使用 MLP；
6. 因此 AFM04 当前阶段的正确目标应表述为：
   “先把 AFM03 Julia 中 stage1 与 stage1pluslight（除 archi screening 外）的功能，用 Python 严格克隆出来，并保持 NN 类型仍为 MLP。” 

当前进一步确认的实施要求

在上面的原则之上，当前还要追加记录以下 4 点，它们应当直接指导 AFM04 下一步实现：

0. AFM04 的 `st1pl` trial 内核需要继续向 AFM03 对齐；
1. AFM04 必须克隆 `trial_opt_enabled = ON` 这条路径，而不能只停留在 `trial_opt_enabled = OFF`；
2. AFM04 还必须完整补上 AFM03 当前 `st1pl` 中那套：
   `step guard`
   `retry`
   `early-stop`
   `ranking`
   全链逻辑；
3. 但 `w_pred` 与 `g_nn / nn_gain` 目前不需要被带入 AFM04；
4. 因此 AFM04 当前应理解为：
   “在保持 MLP 不变的前提下，尽量克隆 AFM03 的 `stage1/st1pl` 主要功能与控制逻辑，但当前明确不保留 `w_pred` 和 `g_nn / nn_gain` 这两个外层机制。”

目标

AFM04 的目标不是做一个“受 AFM03 启发的新实验代码”，而是：

1. 在 Python 环境中重新实现 AFM03 的核心功能；
2. 在功能意义上尽量贴近 AFM03 Julia 主链路；
3. 允许 AFM04 使用 Python 原生生态，例如 `pykan`；
4. 最终使 AFM04 成为：
   一个与 AFM03 平行的、
   但以 Python 为主实现的 HNODE / AFM 代码库分支。


一、这里所说的“克隆”到底是什么意思

这里的“克隆”不是指：

1. 完全逐行翻译 Julia 代码；
2. 完全照搬文件组织；
3. 连内部变量名都一模一样。

这里的“克隆”指的是：

1. 输入数据含义一致；
2. 物理方程一致；
3. rollout 逻辑一致；
4. loss 组成一致；
5. 各 stage 的任务职责一致；
6. 结果文件和可视化在含义上对应；
7. 使用者在 AFM04 中能够完成与 AFM03 中相同的工作流。

也就是说，AFM04 追求的是：

“功能克隆”

而不是：

“逐行翻译”。


二、AFM03 当前主流程到底包含哪些环节

如果从使用者视角看，AFM03 当前主流程至少包含以下环节：

1. 数据与真值准备
   包括：
   数据生成；
   轨迹文件；
   训练/验证用数据集；
   真值 `F_ts` / `x1` / `x2dot` / `x3` 等参考量。

2. `stage1` 与 `st1pl`
   即：
   stage1 主流程中的相关部分，以及 stage1pluslight。
   当前虽然不要求优先克隆 `archi screening`，
   但除 `archi screening` 之外，
   仍应把 AFM03 stage1/st1pl 的主要功能作为 AFM04 当前第一主线去复现。
   同时，当前 NN 类型也应与 AFM03 保持一致，即仍然是 MLP。

3. `st1pl` 结果分析与可视化
   包括：
   ranking；
   3D 全 trial 图；
   GT 附近表现分析；
   各类误差汇总。

4. `st2lw`
   即：
   stage2light_windowed
   主要承担：
   在 windowed 数据上做梯度优化 / 局部 refinement。

5. `st2lw` 结果分析与可视化
   包括：
   loss 曲线；
   mech 曲线；
   `x1/x3/x2dot/F_ts` 对比；
   `NN raw / w_pred / g_nn` 等诊断图
   以及当前窗口的 checkpoint 可视化。

6. `step2b`
   即：
   stage2 之后的进一步训练/微调阶段，
   当前用于 single shooting / multiple shooting 以及后续 L-BFGS 等训练流程。

7. `step2b` 结果分析与可视化
   包括：
   轨迹图；
   loss 图；
   `F_ts / NN` 对比；
   误差统计。

8. 诊断脚本
   包括：
   sensitivity；
   AD vs FD；
   loss component；
   direct chain；
   sanity/selftest；
   这些都属于 AFM03 的工程保障层。

因此，如果说“AFM03 要被克隆到 AFM04”，那被克隆的不只是一个训练脚本，而是一整条工作流。


三、AFM04 需要克隆的流程清单

按照重要性，AFM04 至少要克隆以下流程。

2. RHS 构造
3. ODE rollout
4. loss 计算
5. checkpoint / resume
6. 结果保存

这层不成立，AFM04 就不能算 AFM03 的功能克隆。

AFM03 当前所谓的“第一层”

四、AFM04 中建议明确克隆的主流程顺序

如果从工程角度看，最合理的克隆顺序不是“所有东西同时开工”，而应按以下顺序。

阶段 A：底层功能克隆

1. 数据读取
2. 参数读取
3. RHS
4. rollout
5. loss
6. 结果对象与 checkpoint

这一步完成后，AFM04 应该已经能做：

“给定一个模型参数，跑一段轨迹，并计算损失”

还应明确一点：

AFM04 当前阶段不需要优先克隆：

1. `archi screening`
2. `st2lw`
3. `step2b`

当前最直接、也最必要的目标是：

1. 在 Python 中先把 AFM03 的 `stage1` 与 `st1pl`（除 `archi screening` 外）跑通；
2. 并且在这一阶段保持 NN 类型仍为 MLP。

原因：

1. 你当前并不需要 `archi screening`；
2. 但你现在要求的是“克隆”，因此 stage1/st1pl 中除 `archi screening` 外的其他功能，不应被跳过；
3. `st2lw` 和 `step2b` 的运行都建立在 `st1pl` 结果之上；
4. 如果 `stage1/st1pl` 还没有 Python 版可用，那么后面的局部优化与微调都缺乏入口；
5. 因此 AFM04 当前阶段的第一主线应当是：
   “底层 rollout/loss 成立之后，先克隆 AFM03 的 stage1 与 st1pl（除 archi screening 外），并保持 NN 仍为 MLP。”

阶段 B：先克隆 `stage1` / `st1pl`（除 `archi screening` 外）

AFM04 在这一阶段需要克隆的不是一个“简化版 st1pl”，
而是 AFM03 中与 `stage1` / `stage1pluslight` 直接相关、且不属于 `archi screening` 的功能。

AFM04 要克隆它，至少要复制：

1. 候选生成逻辑；
2. 每 trial 的 rollout + loss；
3. trial 记录；
4. 排名输出；
5. checkpoint / resume；
6. shard / resume log 机制（如果 AFM04 也保留分片并行）。
7. MLP 初始化与前向结构；
8. mech 参数边界与 trial 解码；
9. `stage1pluslight` 当前的 grid-search / seed-bank 逻辑。
10. `trial_opt_enabled = ON` 的 trial 内优化路径；
11. `step guard / retry / early-stop / ranking` 这条控制链。

同时还要强调：

1. 这里克隆的是 `stage1pluslight`；
2. 以及 `stage1` 中除 `archi screening` 之外的相关功能；
3. 当前不要求优先克隆完整 `stage1` 的 archi screening；
4. 当前 NN 类型必须与 AFM03 保持一致，即仍然是 MLP。
5. 但 `w_pred` 和 `g_nn / nn_gain` 当前不作为 AFM04 第一阶段必须克隆的对象。

阶段 C：再克隆 `st2lw`

这是 `st1pl` 之后的下一阶段。
原因：

1. 它仍然直接检验：
   Python 中的 ODE + NN/KAN + backward 是否可行；
2. 但它的候选来源依赖 `st1pl`；
3. 所以它应当排在 `st1pl` 之后，而不是之前。

阶段 D：最后克隆 `step2b`

`step2b` 依赖前面两个阶段的结果，因此最自然放在后面。
它至少要复制：

1. stage2 结果继承；
2. 单 shooting / 多 shooting；
3. 进一步优化；
4. 结果保存与图像输出。

结论：

AFM04 要克隆 AFM03 时，主流程顺序建议明确写成：

1. 底层 rollout / loss / checkpoint
2. `st1pl`
3. `st2lw`
4. `step2b`
5. 诊断与可视化


五、为什么 `st2lw`、`st1pl`、`step2b` 都必须被明确列出

这是因为三者职责不同，不是一个脚本能替代另一个。

1. `st1pl`
   负责：
   全局搜索；
   找 basin；
   筛 mech 和 NN/MLP 候选。

2. `st2lw`
   负责：
   在已选候选附近做 windowed 梯度 refinement；
   属于局部优化阶段。

3. `step2b`
   负责：
   进一步训练或更强优化；
   是后续精修阶段。

因此，AFM04 文档中必须明确写出：

“AFM03 被克隆到 AFM04，不是只克隆一个训练入口，而是要克隆 `st1pl + st2lw + step2b` 这三段流程。”


六、AFM04 当前最合理的克隆原则

1. AFM04 优先克隆 AFM03 的功能，而不是克隆其语言实现细节。

2. AFM04 允许使用 Python 原生技术栈，
   包括：
   `pykan`
   `torch`
   Python ODE / autograd 工具
   只要最终功能意义上贴近 AFM03 即可。

3. AFM04 不要求第一天就覆盖 AFM03 的所有外围脚本，
   但必须从一开始就把主流程边界写清楚：

   `stage1/st1pl`
   `st2lw`
   `step2b`
   数据
   可视化
   诊断

4. AFM04 的第一优先级不是“代码组织像不像 AFM03”，
   而是：
   “当用户想完成 AFM03 中的一项任务时，AFM04 能否完成对应功能”。


七、AFM04 接下来应写成哪些模块

如果继续推进，AFM04 最终建议至少包含以下模块：

1. `data`
   数据读取、窗口切片、真值量准备

2. `physics`
   参数、RHS、真实 `F_ts`

3. `models`
   KAN / 其他 NN backend

4. `rollout`
   ODE 积分、trajectory 生成

5. `losses`
   state / x2dot / x3 / `F_ts` 等损失

6. `stage1pluslight`
   即 `st1pl`

7. `stage2light_windowed`
   即 `st2lw`

8. `step2b`
   后续训练

9. `visualization`
   各阶段图像

10. `diagnostics`
    sanity / debug / gradient checks

11. `io`
    checkpoint / resume / result serialization


八、当前最重要的结论

当前需要被明确记住的结论是：

1. AFM04 的目标是功能上克隆 AFM03，而不是逐行翻译 AFM03；
2. AFM04 的主流程必须明确包括：
   `stage1/st1pl`
   `st2lw`
   `step2b`
3. 最合理的克隆顺序是：
   先底层 rollout/loss，
   再 `stage1/st1pl`，
   再 `st2lw`，
   最后 `step2b`；
4. AFM04 当前阶段不需要优先克隆 `stage1` 的 archi screening，
   但应以“`stage1 + st1pl`（除 archi screening 外）”作为第一主线；
5. AFM04 当前第一阶段的 NN 类型应与 AFM03 保持一致，即仍然使用 MLP；
6. AFM04 当前第一阶段还必须继续补齐：
   `trial_opt_enabled = ON`
   `step guard`
   `retry`
   `early-stop`
   `ranking`
   这些 AFM03 `st1pl` 控制链功能；
7. `w_pred` 与 `g_nn / nn_gain` 当前不要求进入 AFM04；
8. KAN/pykan 应当放在完成这一轮严格克隆之后，再作为后续替换方案进入。
