AFM03：NN替代范围变更与Stage2梯度排查总结
日期：2026-03-24

一、这次NN替代范围的核心更改

过去的Scenario03中，NN只代替F_hertz，动力学中的接触项仍以

    + Fad_eff - F_hertz

的形式进入RHS。也就是说，adhesion项Fad_eff仍然是解析已知项，NN只负责排斥的Hertz部分。

现在的Scenario03中，NN不再只代替F_hertz，而是统一代替净tip-sample contact force：

    F_contact = F_hertz - Fad_eff

因此，动力学RHS被统一改写为：

    x2dot = (Fd*cos(wd*t) - k*x1 - c*x2 - F_contact) / m
    x3dot = (-F_contact - ks*x3) / cs

预测侧对应为：

    F_contact_pred = g_nn * NN(x1, x2, x3) * w_pred

这里有三个要点：

1. NN现在学习的是净接触项F_contact，而不是单独的F_hertz。
2. g_nn的语义也随之改变，变成contact_net模式下的幅值标定。
3. w_pred gate仍然保留，并继续由当前状态下的soft contact gate给出。


二、目前已经确认的事实

1. Stage1、Stage2、Step2b三处的contact_net前向定义是一致的。
   也就是说，从代码静态结构上，没有查到“某一处还在用Hertz-only，另一处已经切到contact_net”的明显断裂。

2. Stage2当前优化的目标仍然是train loss，不是validation loss，也没有被替换成别的目标函数。

3. Stage2当前确实直接使用stage1pluslight candidate自带的p_net_vec与g_nn作为warm start。
   这不是bug，但它意味着Stage2的起点高度依赖stage1pluslight输出的candidate质量。

4. 目前的异常现象不是“retry过多导致无法前进”，而是：
   在W1/W2上，很多case在epoch 1时梯度就已经极小，且loss几乎不下降；
   在W3上，同一套代码下却仍然可以得到明显更大的梯度并发生下降。

5. 因此，“Rank1和Rank8刚好都落在某个basin底部”并不是一个足够有说服力的解释。
   当前更合理的说法是：W1/W2出现了窗口特异的梯度塌缩、梯度失真，或者loss分量之间的梯度抵消。


三、目前遇到的核心问题

当前最重要的问题不是：

    “为什么没有继续retry”

也不是：

    “为什么Rank1和Rank8都恰好掉到同一个basin底部”

而是：

    “为什么在W1/W2上，参数 -> loss 的梯度信息几乎无法有效传导，而W3却可以”

这说明问题更像是一个数值/梯度可信度问题，而不是单纯的优化器是否足够努力的问题。

从现有日志可以概括成：

1. W1/W2：
   梯度在epoch 1就已经非常小，loss、ks/cs、NN的F_contact误差都几乎不动。

2. W3：
   梯度量级明显更大，并且确实还能发生loss变化与参数变化。

3. 所以如果真有问题，它更像是“窗口相关的梯度传导异常”，而不是“整个AFM03链路彻底断掉”。


补充可能性：普通MLP对Hertz/幂律关系的归纳偏置不足

除了“窗口相关的梯度可信度/梯度抵消”之外，目前还应保留另一种结构性解释：

    不是优化器不够努力，而是普通MLP本身对F_hertz/Fts这类幂律接触力的表示不够顺手。

这里要区分两件事：

1. 这并不等于“MLP不能逼近幂函数”。
   从通用逼近角度，MLP当然可以逼近幂函数。

2. 但它逼近这类函数的方式并不自然。
   对于

       F_hertz ~ delta^(3/2)

   这类带有明显物理结构、局部曲率变化快、对indentation高度敏感的关系，
   普通MLP往往只能靠很多平滑非线性片段去拼出来。

因此，即使当前较大的NN已经可以把F_contact/Fts的整体轮廓“包住”，
它仍然可能学不到更细的动态细节，尤其是：

1. 峰值附近的局部曲率变化
2. F_hertz主导区域的细微动态起伏
3. 对indentation变化的精细响应

所以当前瓶颈未必只是“网络还不够大”，还可能是：

    普通MLP这一函数族虽然通用，但对Hertz/幂律型接触力没有合适的归纳偏置。

这条可能性与“梯度可信度问题”并不冲突：

1. 前者解释的是：即使梯度是对的，模型本身也可能不擅长学出目标细节；
2. 后者解释的是：即使模型有表达能力，当前窗口里的梯度也可能传不动。

因此，后续判断时应把这条也作为正式备选解释保留下来，而不是只盯着优化器或retry策略。


补充理解：当前NN的训练成本，本来就不是“普通监督学习里的MLP成本”

还应明确一点：

    当前AFM03里的NN，即使结构上只是普通MLP，
    其训练方式也不是普通 supervised learning 里那种

        x -> y

    的一次前向、一次反向。

在普通监督学习中：

1. 输入通常是一批样本或一整段序列；
2. NN直接输出预测；
3. loss通常直接作用在NN输出上；
4. 每个epoch一般只需要一次普通前向传播和一次普通反向传播。

但在当前AFM03中：

1. NN的输入只是某一时刻的状态，例如

       (x1, x2, x3)

2. NN输出不会直接作为最终监督对象，而是先进入state-space / ODE右端；
3. 系统必须经过数值积分，把每个时刻的NN输出串成整段轨迹；
4. 最终loss比较的是整段积分结果上的

       state / x2dot / x3 / Fts proxy

   而不是某个单点直接标签。

因此，当前NN的真实计算链路更接近：

    state_t -> NN -> RHS_t -> ODE rollout -> whole-trajectory loss

而不是：

    input -> NN -> label loss

这意味着：

1. 前向传播本身已经包含了大量积分器步骤，而不是一次简单矩阵乘法；
2. 反向传播也不是普通MLP backprop，而是要穿过整段积分过程的AD / sensitivity；
3. 所以“当前NN训练很慢”并不只是因为MLP结构大小，而是因为它被嵌进了一个neural-ODE / state-space rollout框架中。

这个理解有两个作用：

1. 它解释了为什么即使NN结构本身不大，整体训练和筛选仍然会很慢；
2. 它也提醒我们：如果未来要替换MLP，不能只比较“某种新网络的表达能力”，还要考虑它被放进ODE积分和sensitivity链路之后的总成本。


补充可能性：w_pred 作为外部门控，可能对NN学习形成次级约束

这条目前应列为“次要怀疑”，而不是首要结论。

当前前向形式是：

    F_contact_pred = g_nn * NN_raw(x1, x2, x3) * w_pred(x1, x3)

其中：

1. NN_raw 负责学习接触力幅值/形状；
2. w_pred 负责接触门控；
3. 最终输出由二者相乘得到。

目前从结果上看：

1. w_pred 已经十分接近 w_true；
2. 这也意味着 x1、x3 的回收已经比较准确；
3. 因此，“w_pred 完全错误地切坏了接触区间”这种强解释，目前证据并不支持。

这里还需要补充一个容易被忽略、但很关键的判断：

1. 从平滑性角度看，w_true 以及当前同型的 w_pred 都不是“粗糙开关”。
   它们本质上来自 softplus/logistic 型软门控，因此在接触切换区附近提供的是高阶平滑，而不只是C1连续。

2. 但“足够平滑”并不自动等于“不会干扰NN学习”。
   问题不一定在于它不平滑，而可能在于：它作为一个放在 NN 外部的 gate，提前规定了接触启闭的参数化分工。

3. 这意味着，即使 w_true / w_pred 本身具有无穷阶光滑性，它仍可能在结构上影响 NN_raw 的学习目标：
   NN_raw 不再直接承担完整 Fts 形状，而是在一个外部门控之后去拟合残余幅值模板。

4. 这种影响在普通 MLP 下可能只是“次级约束”，但如果日后希望切换到 EQL / symbolic NN 等更强调显式结构发现的模型，
   这种外部门控就更值得警惕，因为它可能把本应由模型自己识别出来的接触规律提前写死在网络外部。

但仍然需要保留一种更弱的担心：

    即使 w_pred 基本正确，它作为一个外部门控，仍可能改变NN_raw的最优分工方式，
    从而使NN_raw更倾向于学习一个平滑模板，而不是主动去逼近Fts/F_hertz的复杂局部细节。

也就是说，w_pred 未必是在“给错答案”，但它有可能在参数化层面：

1. 削弱 NN_raw 对细节结构的学习动力；
2. 让复杂的接触开关形状更多由 gate 承担；
3. 使 NN_raw 留在更平滑、更低频的函数族里。

因此，这条应被记录为：

    次要怀疑：w_pred 可能对NN学习形成额外约束，从而部分阻碍其逼近Fts的真正细节规律。

但在当前阶段，它的优先级仍低于：

1. 梯度可信度/梯度抵消问题；
2. 普通MLP对Hertz/幂律关系归纳偏置不足的问题。


四、当前最该查的3件事

第1件事：检查 p_net -> F_contact 这半段的局部灵敏度是否正常

不要一上来就看full loss，先固定当前状态轨迹，只检查：

    F_contact_pred = g_nn * NN(x1, x2, x3) * w_pred

相对于p_net的局部Jacobian或局部敏感度。

目标是回答：

    在W1/W2上，NN本身对参数还有没有正常的响应？

如果这里已经接近零，而W3正常，那么问题就在NN/gate这一半。
如果这里正常，而full loss梯度仍然很小，那么问题就在ODE求解/adjoint/loss组合这一半。


第2件事：检查full loss关于p_net的AD梯度是否可信

当前代码中已经对mech_raw做了AD vs FD检查，但还没有对p_net做同等级别的检查。

接下来应当做的是：

1. 取一个p_net方向v，例如

       v = grad_raw.p_net / ||grad_raw.p_net||

2. 比较两种量：

       AD方向导数 = sum(grad_raw.p_net .* v)

   和

       FD方向导数 = (L(theta + h*v) - L(theta - h*v)) / (2h)

3. 分别在W1、W2、W3上比较。

目标是回答：

    是不是AD/adjoint给出的p_net梯度在W1/W2上已经失真，
    而W3上的梯度仍然可信？


第3件事：检查loss分量之间是否发生梯度抵消

当前Stage2总loss由多个部分组成：

    total = state + x2dot + x3_range + cont + l2

因此一种可能是：

1. state项对p_net/mech的梯度方向是A
2. x2dot项对p_net/mech的梯度方向是B
3. A和B在W1/W2上恰好强烈抵消
4. 导致总梯度很小，看起来像“没有梯度”

这时问题并不一定是AD错了，也不一定是NN链路断了，而是：

    total loss的组合在某些窗口里产生了梯度抵消

因此需要分别对以下分量单独求梯度并比较：

1. state only
2. x2dot only
3. x3_range only
4. total

目标是回答：

    W1/W2上总梯度变小，到底是因为没有梯度，
    还是因为不同loss分量互相抵消？


五、建议的排查方针

方针不是马上继续改优化器，而是按“从局部到整体”的顺序查：

第1步：局部NN链路检查

    先查 p_net -> F_contact_pred 的局部灵敏度，
    不经过ODE求解，不经过总loss。

目的：
    判断NN replacement本身是否还有正常参数敏感度。


第2步：full loss梯度可信度检查

    在同一个theta、同一个窗口上，
    对p_net做AD vs FD directional derivative比较。

目的：
    判断是不是adjoint/AD在W1/W2上给错了梯度。


第3步：loss分量梯度分解

    分别计算state/x2dot/x3_range对参数的梯度，
    再与total gradient对照。

目的：
    判断是不是gradient cancellation，而不是gradient disappearance。


第4步：只在完成以上三步后，再决定是否修改优化策略

如果没有先完成上面的诊断，就直接继续调：

1. lr
2. retry
3. group adapt
4. grad scale

这些都只是在黑箱里继续摸索，无法回答根因。


六、当前阶段的工作结论

1. 目前不应把问题简单解释成“Rank1和Rank8已经精确落在某个basin底部”。
2. 目前也不应简单解释成“仅仅是优化器不够强”。
3. 最应优先排查的，是W1/W2上的梯度可信度问题：

   (1) p_net -> F_contact 的局部灵敏度是否正常
   (2) full loss对p_net的AD梯度是否可信
   (3) loss分量之间是否发生梯度抵消

只有完成这三项检查之后，才能更有把握地判断：

    问题究竟是NN replacement链路、adjoint/AD、还是loss结构本身。
