AFM04 stage1pluslight 候选筛选困境与当前目标总结

一、背景

在 AFM04 当前流程中，stage1pluslight (st1pl) 负责进行大规模 random search，
对候选的 (ks, cs, NN seed, KAN initialization) 组合进行粗筛；
stage2light (st2l) 负责从 st1pl 输出的 warmstart 出发，进行 gradient-based optimization (GBO)，
进一步恢复系统中的关键物理量与隐藏状态，例如 x3, ks, cs, Fts 等。

当前实验已经暴露出一个核心问题：
st1pl 的现有 loss/ranking 机制，并不能稳定地把“最接近物理真值”的候选自动排到最前面。
这不是因为正确 basin 不存在，也不是因为 st2l/KAN 没有能力恢复；
而是因为系统存在明显的 non-identifiability / coupling，
使得许多“物理上不够正确但轨迹上能补偿”的组合，也能取得很好的 loss。


二、目前已经得到的结论

1. st1pl 的大规模搜索是有价值的。

即使当前 ranking 不能直接把最接近真值的候选放到前列，
高密度、大规模 random search 仍然能够在搜索空间中找到一些“突破 coupling”的候选 basin。
换句话说，真值附近的 basin 并不是不存在，而是稀少、且容易被模糊性淹没。

2. st2l / KAN 的恢复能力已经被证明。

当人工从 st1pl 结果中提取出一个足够接近物理真值、且没有严重陷入 coupling 的 rank
并送入 st2l 后，
KAN + GBO 可以成功 retrieve 我们真正关心的信息：
x3, ks, cs, Fts 等。

因此，当前的主要瓶颈不是“模型没有能力恢复真实系统”，
而是“前端筛选机制没有可靠地把正确 basin 自动挑出来”。

3. 当前结果不能被解释为完整 pipeline 已经自动解决不可辨识性。

如果某个 rank 是通过人工观察、人工理解、甚至带有 oracle 性质的方式被挑出来，
那么这个实验的意义是：

- 证明正确 basin 存在
- 证明 st2l/KAN 有能力从正确 basin 出发恢复真实系统
- 证明问题不在模型表达能力本身

但它不能被表述为：
"当前 st1pl -> st2l pipeline 已经能够自动、稳定、公平地恢复真实物理参数。"

否则严格来说，会混入人为先验，构成流程层面的作弊。


三、当前真正的困境

当前困境可以概括为一句话：

"我们已经知道正确答案附近的 basin 可以被找到，也知道一旦进入该 basin，
 st2l 就能成功恢复系统；
 但我们还没有一个在有限计算预算下，能自动把这类 basin 从大量候选中筛出来的机制。"

更具体地说，困难体现在以下几点：

1. loss 最优不等于物理最优。

由于 non-identifiability / coupling 的存在，
许多候选虽然在 ks/cs/x3/Fts 上偏离真实物理，
但依然可以通过补偿关系得到很好的 trajectory loss。
因此，仅按当前 loss 排名，会偏向“可补偿解”，而不是“真实解”。

2. 真值附近候选可能存在，但在 rank 中不突出。

当前观察说明：
接近物理真值的候选并不会自动出现在最靠前 rank。
这意味着 “search space 中存在好 basin” 与 “ranking 能自动选出它” 是两件不同的事。

3. 理论上可以靠更高搜索密度逼近正确答案，但时间预算不允许。

如果把搜索密度继续放大到例如 100 x 100 x 10000，甚至更高，
则有理由相信：
只要搜索足够细、足够广，
最终我们会更容易遇到同时满足以下条件的候选：

- loss 足够低
- coupling 补偿不足以压过真实解
- 物理参数更接近真值

也就是说，在极高密度搜索下，
loss 最优候选更可能逐步靠近真实系统。

但是，这条路线在实际时间预算上不可行。
st1pl 当前已经非常耗时；
如果继续仅靠 brute-force 提高密度，
代价会迅速上升到难以接受。

4. 因此当前问题不是“能否找到”，而是“如何更高效地筛选”。

我们并不是要证明：
"只要搜索得足够大，总会找到。"

这个命题在实验上大概率是对的，但没有工程意义。

我们真正需要解决的是：
"在明显更小的时间预算下，如何筛出一个足够小的候选组，
 使其内部高概率包含接近物理真值、并且不会在 st2l 中立刻掉入 coupling/local minima 的组合。"


四、当前目标

当前 AFM04 的合理目标，不应再表述为：

"让 st1pl 直接给出唯一正确的 top-1 rank。"

而应表述为：

"在有限计算预算下，让 st1pl 从海量候选中筛出一个较小、但高价值的 shortlist，
其中包含至少一个足够接近物理真值、且适合作为 st2l warmstart 的候选。"

这个目标更具体地包括：

1. shortlist 必须小。

它不能大到仍然需要人工在几百上千个候选中肉眼挑选；
否则只是把 brute-force 的负担后移，没有真正解决问题。

2. shortlist 必须保留真值附近 basin。

即使 top-1 不一定正确，
也至少应保证 shortlist 中包含那些：

- ks/cs 更接近真值
- 没有严重陷入 coupling
- 进入 st2l 后有希望继续收敛到正确物理解

的候选。

3. shortlist 的设计目标是提高 st2l 的成功率，而不是只优化 st1pl 的 loss。

换句话说，好的 st1pl 筛选机制不应该只回答：
"谁在当前 loss 上看起来最好？"

而应该回答：
"谁最值得被送进 st2l？"

也就是：
谁最可能在后续 GBO 中避免掉入错误 basin，
并最终恢复真实物理信息。


五、因此我们目前对 AFM04 的正确理解

截至目前，AFM04 已经证明了两件事：

1. 正确 basin 在搜索空间中是存在的；
2. 一旦进入正确 basin，st2l/KAN 有能力恢复真实系统。

但 AFM04 还没有证明第三件事：

3. 现有 st1pl ranking 能够在有限预算下自动挑出这些 basin。

因此，当前工作的重心应该从
"继续证明 KAN 能不能恢复"
转移到
"如何设计一个更合理的 st1pl candidate selection / shortlist mechanism"。


六、后续工作的判据

未来如果某种改进是有效的，它至少应满足以下判据之一：

1. 在相同或更少时间预算下，
shortlist 中出现“接近物理真值候选”的概率明显提高；

2. 在相同 shortlist 大小下，
st2l 的成功率更高；

3. 对人工 oracle 挑选的依赖明显下降；

4. 最终能够更公平地宣称：
"AFM04 pipeline 在有限预算下具备自动恢复真实系统的能力。"


七、总总结

当前 AFM04 的核心问题，不是 recoverability，而是 discoverability。

也就是说：

- 我们已经基本证明了：正确 basin 一旦找到，系统是可恢复的；
- 但我们还没有解决：在有限预算内，如何自动发现并保留这些 basin。

因此，AFM04 当前阶段最重要的目标不是继续无限加大 brute-force 搜索密度，
而是建立一种更高效的筛选机制，
让较小规模的 st1pl 输出中就能包含那些真正值得送入 st2l 的候选。
